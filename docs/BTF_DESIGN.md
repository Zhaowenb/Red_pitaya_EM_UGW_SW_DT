# BTF 移植设计

## 原则与组成

2026-10-11，以 Pico BTF 的共享界面和分析/偏置工作流为参考，以 Red Pitaya 主线 `a43646c` 的设备与任务实现为硬件基础。只在独立 `red_pitaya_btf` 目录开发，上传目标为同一仓库的 `btf` 分支。

```text
浏览器：共享 Shell / Stage / Inspector + 单数据分析状态对象
    ├── 仪器 API → WebControlState / BiasScanWebMixin → 单一硬件任务
    │       ├── RedPitaya → Unix socket → C++ 官方 API → ADC / DAC
    │       └── 偏置控制器 → 可选 IT6524D USB / 仿真电源
    └── 分析 API → 有界分析进程 / 轻量即时请求 → NumPy
数据：HANNSCOPE_DATA → captures / sweeps / lcr / bias_scans / analysis_exports
```

前端保留原 BTF 节点 ID、事件和数学绘图，视图模块移动原节点，不复制第二套表单。`board.js` 与 `port.js` 在 BTF 视图重排前加载，附加板卡能力与参数构造；`btf.js` 最后约束偏置通道与不支持的功能。独立分析页使用 `shell-board.js` 提供品牌和返回主菜单。

默认深色，继续支持浅色、强调色、专注、抽屉及 reduced-motion。文件与遥测进入顶部工具抽屉，采集/扫描设置按 BTF Inspector 分组。导航使用本地 SVG，历史 A–H 颜色仍保留。

## 数据与分析

保留 Red Pitaya NPZ 展开预算、上传限制、路径边界、分析取消、轮流输出维度和校准设备签名。BTF 引入可读任务命名、持久化导出会话标识和 ZIP；数据与命名偏好放到 `HANNSCOPE_DATA`，不依赖 `/opt` 是否可写。

原始采集自动存 NPZ；手动 NPZ 与 CSV 保存共享独立导出会话和文件 stem，不覆盖输入文件。滤波派生文件进入 `analysis_exports`，处理元数据保留原始路径；重新评价另存报告。

通过相同确定性波形对比参考模块的零相位带通、三种时频算法、空间—时间对称性 TEST 和 N/f 评价；CWT/STFT 保留主线有界内存实现，容差见回归 JSON。没有把模型回波或仿真诊断当作物理缺陷标定。

## 偏置任务适配

任务冻结当前采集快照，重新计算记录长度；预检覆盖所有激励幅值，检查精确采样率、记录预算、输出偏置/负载上限和 ADC 角色。固定单输出，不将轮流采集的首条路径冒充完整统计。PZT 与可选监测通道互不重复。

继承偏置控制器的先断电后分析/落盘、独立计时、过流、稳定性、冷却、停止、输出未知锁定、OFF-only 恢复和原始重复保存。默认无 USB/PyVISA 依赖也可运行仿真与离线分析；真实电源需要可选依赖和现场安全参数。

新增硬件进程 `OFF`：在硬件互斥锁空闲时确认两路 DAC 禁用；忙时拒绝确认。Python 调用该指令不设置持久取消位，因此电流档间关断后仍能继续下一档。实际 C++ 构建、关断与电源联机须在板上再次验收。

客户端租约覆盖偏置扫描；关闭页面或租约超时停止任务。退出 Web 服务先停止偏置电源与硬件任务。不支持的三 ADC 波形保护、自动输入量程和三 ADC 现场测量在 UI 与 API 双层限制。
