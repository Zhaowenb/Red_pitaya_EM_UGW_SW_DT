## 本机运行

在项目目录执行 `./start-local.ps1`，浏览 `http://127.0.0.1:4825/measure`。
也可指定 `-PythonExe` 和 `-Port`。运行依赖 Python 3.10+、NumPy；不依赖 PicoSDK。
启动只监听 127.0.0.1。测试时在相应页面显式勾选“仿真”；页面刷新不会默认勾选。
数据写入 `app/data`，本机服务不通过网络远程操作板卡。

LCR 页上方选择输出端口、负载与触发模式；两路输入量程必须对应实际 LV/HV 跳线。LCR 不采用轮流/联合激励，避免将联合响应错误解释为单一阻抗。

历史归档在顶部上传 ZIP，返回目录会填入三个 LCR 归档路径。带校准的历史小信号归档重算依赖对应校准文件；缺少文件时报错。单独的校准 JSON 可以上传到校准列表，Pico 校准不能直接当作 Red Pitaya 的硬件校准。

干扰页使用专用 ZIP 导入按钮，要求包含 `session.json`、`runs/*.npz`。重新分析修改的是导入副本，源 ZIP 和原目录不变。

## 9 月 27 日追加：双输出相位与细节核对

本机全套 Python 回归：66 项通过（19.237 s）。浏览器已检查 STFT 的 IN2/B 选择与计算、A/B 空间—时间对称性、滚轮时间缩放、Shift＋滚轮幅值缩放及双击恢复。以上为本机仿真/文件分析验证，不是板端验收。

- 双输出相位：原代码将载波相位直接传给任意波形发生器，无法表达“包络固定、载波相移”的 Hann 激励。现在各路缓冲区直接包含载波相位，硬件 API 相位传零，仍使用同一次双路触发。180° 反相、90° 正交、相位环绕及消振相对相位均有回归测试。尚未确认板上原固件中相位失效的完整原因，也未实测修复后的电压。
- 同步起发不等于同相；固定相位差要求同频。自定义 CSV 没有载波定义，相位表示整段循环移位；爬升保持的直流保持部分不随载波相位改变。
- 联合激励仿真不再简单乘以 1.7，而是分别生成两路含相位的响应再叠加。它仍是流程测试模型，不是换能器物理标定。
- 外部触发后的输出持续时间从检测到触发后计时，避免等待外部边沿的时间被算入波包时间；只计算实际启用输出的持续时间。此 C++ 修改尚待 ARM 编译与实机验证。
- 小信号输入溢出会拒绝阻抗计算；仿真校准不得用于实测；校准签名包含端口、负载与相位。
- 大信号与小信号任务支持暂停互斥；停止保留已落盘记录；显示滤波不修改原始记录。
- LCR 归档重算和线性度计算使用可取消的分析进程；报告另存。历史绝对校准路径不能自动猜测，需要导入对应校准文件。
- IN1/IN2 是现场实测通道，A～H 仅用于历史文件；三通道新采集明确不支持。IN 量程是物理跳线约束，不能提供虚假的软件自动换挡。

9 月 28 日追加：输出参考预览支持选择 OUT1/OUT2，使用各路载波相位、独立 OUT2 参数及相应 Vpk，并增加预览与 DAC 缓冲数值一致性测试。参考曲线仍不是实测证明。非独立采集任务拒绝旧的发射切换请求，防止 LCR 当前结果被历史采集替换。

双路相位与独立 OUT2 参数应在板端示波验证中一并核对。部署前还需 ARM 构建、固件 API/DDR 能力核验及接线确认。本轮没有连接或部署 192.168.10.68。
