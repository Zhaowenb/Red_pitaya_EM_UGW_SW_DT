# Pico BTF → Red Pitaya 功能对照

| Pico BTF 功能 | Red Pitaya BTF 处理 | 状态/边界 |
|---|---|---|
| 共享 Shell / Stage / Inspector | 移植共享 UI、文件选择与分析状态对象 | 本机验证；默认深色 |
| 实时测量 | IN1/IN2，LV/HV 跳线、ADC 触发、5 MS/s×10 ms | 仿真通过；本次未实机复验 |
| 单输出 AWG | 保留主线两路 DAC 与相位实现 | 已有主线实测报告，不代表 BTF 新验收 |
| 扫频/周期/二维 | 四路径分组、N/f、排名、停止保留数据 | 本机通过；监测通道不参与接收排名 |
| 单数据分析 | 时间/幅值缩放、平移、游标、零相位带通、多窗口 FFT/PSD | 历史 A–H 和板卡 A/B |
| STFT/WPD/CWT | BTF 控件/状态 + 主线有界内存算法 | 同输入数值对比通过 |
| 空间—时间对称性 | BTF 工作流与原算法 | TEST，证据输出，不判定缺陷 |
| 参数数据分析 | 热图、逐点/逐次、原始波形、重评与推荐 | 上传归档或数据目录，原始不覆盖 |
| 小/大信号 LCR | 两路 V/I 监测，输出与负载身份校准 | 固定物理量程；仿真校准不能实机使用 |
| 三路线性度现场采集 | 明确拒绝 | 可分析历史三路档案 |
| 偏置×幅值扫描 | 单个 OUT1/OUT2 + PZT + 一路可选监测 | 本机仿真；不混合两条发射路径 |
| 电流/电压/PZT 三路保护 | UI 禁用、API 拒绝 | 两路 ADC 不满足要求 |
| ADC 自动量程 | 不提供现场自动切换 | LV/HV 必须匹配跳线 |
| IT6524D USB | 继承可选 SCPI 驱动、资源刷新、未知锁定与断电恢复 | mock 测试通过；板端 USB 未实测 |
| 温度冷却 | 保留线圈温度适配接口与软件冷却 | 无传感器时不假造温度；CPU 温度独立 |
| 磁路诊断 | 模型与可视化预览 | 无硬件接口，启动锁定；三通道均为模型 |
| 干扰实验 | 导入 ZIP 副本、恢复、比较、重评、导出 | 三通道现场实验不支持 |
| 保存命名与完整任务 ZIP | 数据目录持久化命名、唯一编号、同会话多格式 | 不修改参考仓库、输入或已保存目录名 |
| 本机绝对路径 | 替换为板端受控数据根与上传 | 不访问用户电脑任意目录 |
| 设备菜单、图标、返回主界面 | 保留 hann_scope 入口，补充 BTF 标识与顶层返回 | GitHub 分支交付，未部署 |

GUI/CLI 中 PicoSDK 的硬件实现不移植；Red Pitaya 保留独立 C++ 服务。仿真算法测试中的八通道夹具只用于离线回归，不是现场能力。
